# Обновления ObjectManager и headless ИИ

## Изменения данных

`ObjectManager.update/updateObjects` изменяют только существующие ID. Если хотя бы один ID отсутствует, весь пакет отклоняется до записи. Для вставки используйте `add`, для полного набора со стабильными ID — `reconcile`.

```js
manager.beginBulk();
try {
  manager.updateObjects(changedObjects);
  manager.removeObjects(deletedIds);
} finally {
  manager.endBulk();
}
```

Вложенные bulk-блоки откладывают инвалидацию и отрисовку до внешнего `endBulk`. Изменения координат и свойств без смены топологии сохраняют GPU-пакет. Смешанные пакеты точек, линий и полигонов обрабатываются целиком.

`FeatureSource.reconcile(features, equals?)` и `ObjectManager.reconcile(objects, equals?)` используют общий diff по ID. Неизменившиеся записи сохраняют ссылки и состояние. По умолчанию сравниваются структуры JSON-подобных записей; для версионированных данных можно передать `(previous, next) => previous.properties.version === next.properties.version`. Компаратор должен учитывать все изменения, влияющие на отображение. Не мутируйте ранее переданные объекты на месте.

```js
const manager = remoteObjectManager({
  loader: loadVisibleObjects,
  reconcile: true,
});
```

Remote reconciliation включается явно и несовместима с `replace: false`. ID должны быть уникальными и стабильными между загрузками.

## Сцена и запросы карты

Сцена использует bbox-индекс, видимое окно с запасом и журнал изменённых ID. При неизменной камере пересчитываются стили и геометрические представления изменённых видимых объектов. Иконки и подписи используют общий результат компоновки коллизий. Символы обновляют отдельные 16-float GPU-записи, линии и полигоны сохраняют неизменённые подготовленные записи.

Функция `style` должна быть чистой относительно объекта и переданного контекста. При изменении внешних настроек вызывайте `setStyle`, чтобы сбросить кэш. Перемещение камеры, смена фильтра, масштаба, атласа и состава объектов могут потребовать полного обновления видимой сцены. Компоновка коллизий и рисование по-прежнему зависят от числа видимых элементов; весь кадр не становится O(k).

`map.query` возвращает ID и объект владельца для дочерних слоёв менеджера без второго hit-test. Самостоятельные слои сохраняют собственный контракт запроса.

## ИИ: контекст, транзакции и транспорт

`points.replace` заменяет указанную коллекцию; `clearMap` отдельно управляет очисткой остальных коллекций. Обязательные поля проверяются как собственные свойства. JSON-ключ `__proto__` сохраняется как данные.

`engine.getContextSummary(idLimit = 24)` возвращает ограниченные метаданные без сериализации геометрий. `engine.getObjects(collection, ids?)` возвращает изолированные копии выбранных объектов. `engine.queryObjects` — headless API для серверного адаптера:

```js
const page = engine.queryObjects({
  collection: 'places',
  bbox: [37, 55, 38, 56], // west, south, east, north
  where: { active: true },
  search: 'парк',
  fields: ['title'],
  limit: 100,
});
// page.objects, count, geometryCounts, revision, nextCursor
```

Геометрия включается только при `includeGeometry: true`. Лимит страницы — 1–1000, полей — до 64. Cursor действует только для той же ревизии и параметров; после изменения данных запрос нужно начать заново. Bbox проверяет пересечение ограничивающих прямоугольников, а не точное пересечение геометрий. Результат ограничен по количеству, но поиск и подсчёт пока сканируют коллекцию. Готовый HTTP endpoint для этого метода не добавлен: авторизация, доступные коллекции и поля остаются ответственностью host.

Транзакционное событие содержит упорядоченные дельты без полного `snapshot`. Результат `executeTransaction` сохраняет ленивый `value.snapshot` для совместимости: его чтение или сериализация материализует снимок. Проекция применяет дельты в общем batch и откатывает данные, сцену и маршруты при ошибке. Неизменённые записи внутреннего состояния разделяются; изменённая коллекция всё ещё требует поверхностного копирования Map.

`createAILLMAgent({ ..., maxToolCalls: 64 })` ограничивает число исполнений инструментов за запуск (допустимо 1–1024). Отмена проверяется после ответа модели и между инструментами. Уже начавшийся внешний инструмент должен самостоятельно учитывать переданный signal.

HTTP-адаптер принимает `maxEventQueueBytes` (по умолчанию 1 МиБ, минимум 1024). При переполнении SSE отправляет `resync_required` с причиной `slow_consumer`, закрывает поток и снимает подписку. Клиент должен закрыть EventSource, получить свежий snapshot и подключиться снова с проверкой ревизий. Автоматическое переподключение без resync не восстанавливает пропущенные дельты. Очередь может превышать бюджет на размер небольшого завершающего события; сериализация одного большого события остаётся временной аллокацией.
