A browser map engine you can read end to end.

Orihon starts at a 16 KiB core and goes to a million application objects on the GPU without swapping libraries halfway through the project. Strict TypeScript, one options object per call, units in the names, and a size budget that fails the build when it slips.

$ npm i orihon
$ npm create orihon-app my-map

Starting from nothing? The second command writes a project that already draws a map, with the stylesheet, a sized container, attribution and one sample of every Easy overlay in place. Templates: vanilla, vanilla-ts, react, react-ts, cdn.

What you get for reading one page of docs

The parts of an API that decide whether you enjoy the next six months are small, boring and mostly about naming. Orihon spends its budget there.

Two sentences, not five

map.addMarker({ … }) for ordinary application work, marker(position).addTo(map) when you compose layers yourself. There is no third generic map.add({ type }) dialect and no positional Easy overloads to memorise.

Units live in the names

radiusPixels, radiusMeters, durationMs. Coordinates are { lat, lng }, so a bare tuple can never silently swap the two — and latLng(), lngLat() and fromGeoJSONPosition() name the order when you convert.

You choose what ships

Core, Standard and Advanced describe capability, and the ObjectManager sits on top of Advanced because that is where the WebGL it needs already lives. Draw tools, controls, locales and React are separate opt-ins that add single-digit kilobytes. npm run size fails the build when a published artifact crosses its budget, so the numbers below are enforced rather than aspirational.

GPU is a decision you make

renderer: "auto" prefers WebGPU, then WebGL, then DOM. renderer: "webgl" is a requirement: unsupported hardware throws UnsupportedCapabilityError instead of quietly profiling as a DOM path in production.

Typed all the way down

Declarations are generated for every entry point. Events are typed by name and payload, cancellation is AbortSignal, teardown is an idempotent destroy(), and calls after it throw DestroyedError rather than pretending to be cancelled.

Your data has one home

FeatureSource is a versioned store that feeds GeoJSON layers, labels and high-volume rendering at once. Map state and application state cannot drift apart, because there is only one copy.

Nine languages in the shipped UI

English plus ru, ar, tr, zh, de, fr, da, hi — zoom, scale, layers, geolocation, popups, the draw toolbar and fullscreen. map.setLocale("ru") relabels live controls, ar sets RTL, and the packs are a separate 2 KiB import an English-only app never downloads.

It speaks to the GIS you already run

wmsTileLayer() and wmtsTileLayer() for the servers you have, createWMTSFromCapabilities() to configure one straight from its capabilities document, orihon/mvt, orihon/pmtiles and orihon/mlt for packed vector tiles, and offlineTileCache() for the field. No provider is compiled in — a basemap is a template string.

An agent can drive it safely

With orihon/ai a model states a goal — not map calls, not route geometry. The runtime compiles it against a capability registry, previews every step on a private engine fork, and commits one revision; a route stays reactive afterwards, so removing a stop recalculates the rest with no second model call. Bad input comes back as { code, path, message } instead of a half-applied map. See how it works ↓

orihon/ai

Agent-native maps

A separate entry point that exposes the map as a safe, stateful tool environment for an LLM or an agent — not a websocket that forwards tool calls. The model states one goal; the runtime compiles it against a capability registry, previews every step on a private engine fork, and commits the whole thing as one revision. It owns only what it created.

On main, not in 2.0.1 yet

This one is not in the published package: npm i orihon gives you 2.0.1, which has no ./ai export. Read it on GitHub, or install from the repository, until it ships in a release.

Goals, not map calls

create_visit_route carries places and route constraints — not a precomputed route. The runtime compiles it into object-manager → route-model, and the route stays reactive: remove a stop later and the remaining ones are recalculated without another model call.

Repairable, never half-applied

Bad input never throws — it comes back as { ok: false, error: { code, path, message, received } } with the path naming the offending field, which is what an agent needs to fix its own output. A rejected intent commits nothing. Schemas ship as orihon/schema/scene-v1.json.

Sessions, not a global map

createAIAgentSession({ id, engine }) is user-scoped: its own revision, capability allowlist and local UI state. Clearing an AI session resets what the agent made and leaves your own layers alone.

The adapters you already use

One tool vocabulary from listAISessionTools(), exposed through WebMCP (installAIWebMCPTools), AG-UI (createAIAGUIAdapter), an HTTP/SSE handler (createAIHTTPHandler) and an OpenAI-compatible LLM adapter. No second dialect to learn.
