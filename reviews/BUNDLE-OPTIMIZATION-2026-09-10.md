# Оптимизация браузерной сборки — 10 сентября 2026

Изменения выполнены в текущем рабочем дереве Orihon 2.0.1. Исходные размеры сохранены в `bundle-size-before-2026-09-10.json`. Пакеты не публиковались.

## Что изменено

1. Все браузерные ESM-точки входа собираются одним вызовом esbuild с общими чанками. Классы, реестры и React-контекст больше не получают отдельные реализации в каждой сборке. Имена свойств ESM сохраняются для совместимости с пользовательскими объектами и расширениями. Однофайловый IIFE остаётся отдельным самодостаточным артефактом.
2. ObjectManager больше не импортирует тепловой рендер статически. Первый переход к heatmap загружает общий модуль; до этого тепловая карта, её WASM-изолинии и WebGPU-backend не входят в начальную загрузку менеджера. После загрузки строится актуальная сцена, а не снимок старых данных. Удалённый менеджер не создаёт слой после завершения загрузки.
3. Методы изменения данных сохраняют синхронные возвращаемые значения. Первый показ тепловой карты теперь включает асинхронную загрузку модуля; событие `render` этой ветки откладывается до доступности рендера. Добавлено `sceneerror: { error }`; прежний контракт `error.phase: "layout"` не изменён. После неудачи загрузчик освобождает свой pending Promise для следующей попытки; возможности повторной сетевой загрузки также зависят от кеша модулей браузера.
4. В браузерных артефактах из встроенного WASM удаляются только секции `name` и `producers`. Исполняемые секции, экспорты, импорты и `target_features` сохраняются. Исходники с отладочной информацией остаются доступными.
5. В известных литералах GLSL/WGSL удалены комментарии, пустые строки и лишние пробелы. Имена, числовые значения, операторы и границы строк директив не меняются; произвольные шаблоны, включая HTML, не затрагиваются.
6. Объединены два одинаковых пути создания теплового слоя ObjectManager, очистка heat-слоя, увеличение WASM-памяти и Base64-декодирование для cluster worker. В worker передаётся самодостаточная функция, поэтому общий декодер не создаёт недоступных замыканий в другом потоке. Разные пространственные индексы и CPU/GPU-алгоритмы сохранены.
7. Манифест учитывает статические `import` и `export ... from`, хранит вклад исходных модулей и полные начальные зависимости. Добавлены бюджеты совместной загрузки. При упаковке копируются все чанки и сохраняются их побочные эффекты для последующей сборки приложением.

## Измеренные размеры

КиБ gzip, уровень 9. Для каждой строки суммируется полный набор синхронных JS-зависимостей; в совместных сценариях каждый файл считается один раз. CSS, заголовки HTTP и последующие динамические импорты сюда не входят.

| Набор | До | После | Изменение |
|---|---:|---:|---:|
| Advanced + ObjectManager | 209,59 | 160,85 | −23,3% |
| Standard + ObjectManager + React + React ObjectManager | 260,92 | 113,75 | −56,4% |
| ObjectManager | 95,41 | 82,32 | −13,7% |
| React ObjectManager | 97,12 | 79,27 | −18,4% |
| Однофайловый Advanced IIFE | 121,38 | 120,35 | −0,8% |
| Core отдельно | 16,00 | 21,83 | +36,4% |
| Standard отдельно | 36,96 | 47,78 | +29,3% |
| Advanced отдельно | 114,18 | 128,84 | +12,8% |

Общая сборка оптимизирует совместное использование модулей, но не уменьшает каждый отдельный набор. В общих чанках сохраняются реализации, нужные другим точкам входа, и появляются дополнительные запросы. Рост Core/Standard указан в README и бюджетах открыто. Controls/Draw раньше имели внешние зависимости, которые старые цифры не учитывали полностью; сравнивать их прежний вес файла с новой полной загрузкой некорректно.

Уменьшение начальной загрузки ObjectManager частично означает перенос байтов на первый вызов heatmap, а не исчезновение этих байтов. При работе с теплом они будут загружены.

## WASM: встроенный или отдельный файл

Сравнение исходных модулей до удаления метаданных:

| Kernel | gzip Base64, байт | gzip бинарного WASM, байт |
|---|---:|---:|
| MVT tile | 4592 | 3314 |
| Cluster index | 5542 | 4056 |
| Heat field | 1241 | 955 |
| Heat isolines | 4381 | 3271 |

Бинарные файлы экономят около 4,1 КиБ gzip суммарно в этом отдельном измерении; эффект внутри общего JS может отличаться. Их принудительное выделение добавило бы сетевые запросы и изменило бы синхронную инициализацию существующих WASM API. Поэтому встроенный формат сохранён, отладочные секции удалены в сборке, а тепловой набор загружается вместе с отложенным heat-модулем. Это сохраняет резервные JS-пути и однофайловую поставку.

## Проверки

- Сборка и проверка типов прошли.
- Полный набор unit-тестов: 656 успешно, 1 пропущен, 0 ошибок.
- Полный набор браузерных проверок прошёл: общие классы, отложенная загрузка/удаление менеджера, GPU tiles, GeoJSON ingestion/query, heat WASM/contours, PNG export, popup geometry, P1, скорость ObjectManager, camera warp и пиксельная проверка WebGL points.
- Дополнительная проверка блокирует загрузку heat-чанка: получено `sceneerror`, необработанных Promise rejection нет.
- Бюджеты индивидуальной и совместной загрузки проходят. Начальная загрузка ObjectManager проверяется на отсутствие heat-реализаций по метаданным сборки.
- WASM-модули после обработки валидны, экспорты/импорты и target features совпадают. Браузерные проверки вычислений не обнаружили перехода с рабочего WASM на JS из-за упаковки.
- В локально подготовленной браузерной поставке разрешаются все 216 относительных статических и динамических импортов.
- `docs:check` генерирует документацию, затем сравнивает её с Git HEAD. Он не проходит из-за уже существовавших незакоммиченных изменений generated developer guide; эти изменения не откатывались. Это не ошибка компиляции или тестов библиотеки.

Логи: `bundle-unit-tests.log`, `bundle-browser-tests.log`. Дополнительная проверка сетевой ошибки выполнена после полного браузерного прогона.
