# Проверка сравнительного бенчмарка — 2026-09-10

Изменены `examples/bench-compare/index.html`, README, добавлены переиспользуемый harness и его проверки. Предшествующие изменения библиотеки сохранены. Сервер: http://localhost:4176/examples/bench-compare/.

## Найденные проблемы и исправления

1. **Неравный масштаб камер.** MapLibre использует мировой размер 512·2^zoom, остальные адаптеры — 256·2^zoom. Приведены начальные камеры и jumpTo к zoom−1 для MapLibre. Проверка native picking до исправления: 75 видимых образцов у Orihon и 18 у MapLibre; после — 75 у обеих библиотек. В JSON добавлен pixelsPerLongitudeDegree.
2. **Leaflet.markercluster не использовал chunkedLoading по назначению.** Группа добавлялась на карту после addLayers. Теперь группа сначала подключается, обработка идёт порциями с chunkInterval=16, а тест ждёт chunkProgress(done===total). При отключённой подложке карте явно задаётся maxZoom=19, необходимый плагину. Фильтрация ждёт завершения reclustering перед следующим шагом.
3. **Большие синхронные преобразования данных.** Подготовка Feature/marker/GeoJSON переведена на ограниченные порции, где это контролирует адаптер. Приоритет — scheduler.yield, запасной вариант — таймер. Паузы входят в Load. Leaflet canvas подключается порциями по 10k: порции по 1k приводили к чрезмерным повторным перерисовкам растущего набора.
4. **Короткое ожидание принималось за готовность.** В point/live/native-pick адаптерах OpenLayers используется rendercomplete; источники MapLibre ожидают sourcedata и isSourceLoaded без лимита 30–180 секунд. Отмена снимает подписки ожидания; ошибки сохраняются в строках. Синхронный код самой библиотеки прервать невозможно.
5. **Неоптимальные адаптеры.** OpenLayers не строит hit-detection проход в неинтерактивных points/live сценариях; стили обычных кластеров кэшируются по размеру. Live меняет один и тот же набор ID: 20% или 1%; Orihon обновляет изменённые индексы, MapLibre пересчитывает только изменённые координаты, сохраняя одну загрузку буфера. Время загрузки live больше не фиктивный ноль.
6. **Старый Pick не проверял индекс или API hit-test.** Он выполнял собственный O(N) перебор. Переименован в диагностический Projection + linear scan; добавлен Native hit-test с публичными API и проверкой попаданий. Leaflet честно сообщает n/a, поскольку прямого эквивалента публичного запроса отрисованных объектов нет.
7. **Сравнение raw GL с полноценными Feature.** Сохранено как отдельный тест специализированных путей; добавлен Native point features. Различия семантики и стоимости объектов описаны, общий победитель не подсвечивается.
8. **Сетевая подложка и порядок участников влияли на результат.** Подложка отключена по умолчанию в overlay-тестах и включается отдельно. Порядок библиотек чередуется между повторами. В экспорт входят отдельные попытки, порядок, viewport, seed, распределение и политика кэша. Три повтора не полностью балансируют четыре позиции; cold-start не заявляется.
9. **Измерение размера путало transfer и body, учитывало первую запись.** JS/CSS переведены на pinned jsDelivr URLs с доступным Resource Timing. Суммируются все наблюдаемые запросы; фактический transfer, encoded body и недоступные записи различаются. Для ограниченных серверов есть отдельная CORS-загрузка с подсчётом decoded bytes. Она не выдаётся за сжатый размер исходного запроса.
10. **Отмена/ошибка оставляла ресурсы и неполные строки.** Карты и менеджеры регистрируются сразу после создания, освобождаются при переходе/ошибке. Отмена отмечает незавершённую строку, завершённые результаты можно экспортировать. Добавлены прошедшее время, статус, число и максимум long tasks. Уход вкладки в фон отмечает попытку как недостоверную.
11. **Несопоставимые счётчики.** Число всех сохранённых маркеров Leaflet больше не выдаётся за число видимых кластеров. У MapLibre исключено двойное включение слоя подписей. Счётчики рендереров всё ещё имеют разные семантики и не служат общим знаменателем.

## Добавленные сценарии

- Native point features — полноценные публичные объекты/Feature.
- Sparse live updates — 1% изменённых объектов.
- Native hit-test APIs — реальные поисковые API с проверкой попаданий.
- Три распределения точек: regional uniform, dense hotspots, worldwide; фиксируемый seed и одинаковые префиксы наборов при разных N.
- Long tasks, полное время прогона и статус достоверности — для всех сценариев.

## Проверки

Проверки harness: миллион элементов без потери ID, отмена между порциями, ожидание готовности/очистка слушателей, cache hit против закрытого timing, суммирование запросов, порядок участников, синтаксис всех встроенных адаптеров, соответствие UI таблице сценариев и синхронность inline-копии harness.

В браузере пройдены Points для всех четырёх библиотек на 1k и 1M, новые native feature/native pick/sparse сценарии на 1k. В native pick после выравнивания камер: Orihon 75/75, OpenLayers 74/75, MapLibre 75/75; различие одного попадания отражает разные правила выбора/размеры символов, а не скрытое исключение образца. Отмена длительного Leaflet-прогона проверена: интерфейс вернулся в рабочее состояние.

Дополнительно: Leaflet.markercluster на 100k завершился за 8,93 с (Load 5,05 с, JS heap 367 МБ); фильтр Leaflet после исправления отсутствующего maxZoom завершился на 1k. Heatmap на 1k прошёл у всех четырёх библиотек. Все 8 проверок benchmark-contract + benchmark-harness проходят. При проверке масштаба использован один и тот же набор и одна область карты; допуски native hit-test различаются и указаны в коде (OL hitTolerance=3).

GeoJSON на 1k также прошёл у всех четырёх библиотек. Native point features проверен с тремя повторами: все четыре строки завершились с median×3. Это проверка исполнения и агрегации, не сертифицированный рейтинг производительности. Для points/live установлен одинаковый номинальный диаметр 4 px; форма символов и аппаратная плотность пикселей всё ещё зависят от рендера.

Итоговый полный 1M прогон: regional uniform, seed=12345, номинальный диаметр 4 px, выровненный масштаб камер, без сетевой подложки, один повтор:

| Адаптер | Load | Wall | Длинные задачи / максимум | JS heap вкладки |
|---|---:|---:|---:|---:|
| Orihon WebGL | 200 мс | 3,55 с | 2 / 61 мс | 112,6 МБ |
| Leaflet canvas | 34,80 с | 38,59 с | 126 / 1506 мс | 1,57 ГБ |
| OpenLayers WebGLPoints | 6,60 с | 9,86 с | 41 / 3535 мс | 2,74 ГБ |
| MapLibre raw GL | 212 мс | 3,78 с | 2 / 287 мс | 2,78 ГБ |

Все четыре строки завершились Complete, вкладка сохранила работоспособность. Во время длинной задачи OpenLayers чтение DOM временно превысило таймаут инструмента управления браузером; сам бенчмарк продолжил ждать и успешно завершился. Таблица не является сертифицированным рейтингом скорости: это одиночный прогон в In-app browser на текущей машине. Абсолютный heap поздних библиотек включает неубранные предыдущие аллокации, поэтому его нельзя считать памятью конкретной библиотеки. GC не гарантирован; GPU и worker-память измерены не полностью.

## Что предложено убрать из основного сравнения (ничего не удалено)

Предложения приняты пользователем и реализованы: линейный поиск и его пресет перенесены в Diagnostics, оба сценария изолиний и их пресеты — в Orihon capabilities. По запросу пользователя сетевая подложка теперь включена по умолчанию; её можно отключить для изолированного измерения оверлеев. Приведённый выше исторический прогон 1M выполнен без подложки, как указано в его условиях.

- Перенести Projection + linear scan в диагностику: для интерактивной карты полезнее Native hit-test.
- Перенести Isolines и Heatmap + isolines в группу возможностей Orihon; объединять их можно, если отдельная цена контуров не нужна.
- Не удалять Clusters/Filter, Basemap/Tile scroll, Live/Sparse: у пар разные нагрузки.
- Rich OM оставить интеграционным сценарием, не заменять им отдельные тесты.
- DOM markers переосмыслить как сравнение способов отображения: нынешние HTML/SVG/canvas/GPU варианты не равны по работе.

## Границы достоверности

Порционная подготовка и отсутствие короткого таймаута не гарантируют защиту от настоящего OOM или зависания драйвера. У Leaflet миллион объектов уже требует гигабайт памяти. Если процесс исчерпает память, JavaScript не сможет «подождать и восстановить» его. Ограничения DOM и больших per-feature линий сохранены и явно показываются. Нативные синхронные фазы всё ещё создают long tasks; RAF не является счётчиком полностью готовых GPU-кадров. Для публикации численного рейтинга нужны повторные прогоны в отдельных чистых браузерных процессах, фиксированное оборудование, одинаковая видимость и семантика символов.
